基于 [LLM Wiki 模式](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f) 构建的个人知识库。

## 快速开始

1. 用 [Obsidian](https://obsidian.md) 打开本文件夹
2. 启动 AI 助手：`claude`
3. 开始你的第一次摄取

## 操作

### 1. 摄取（Ingest）— 添加知识

将源文档放入 `raw/` 或直接提供 URL：

```
摄取这篇文章：https://example.com/some-article
摄取所有新资料
```

LLM 会阅读源文档，保存到 `raw/`，在 `30 证据/` 创建 `source` 资料摘要页，在 `20 领域/<领域>/工作台/原子卡/` 生成 `atom` 草稿，并更新操作日志。

源文档中的核心观点应提炼为 atom，再整合到稳定知识页（`10 核心/` 或 `20 领域/`）。

### 2. 查询（Query）— 提问

```
X 和 Y 之间有什么关系？
对比 A 和 B
总结我们知道的关于 Z 主题的所有内容
```

LLM 默认优先查阅稳定知识层（`10 核心/`、`20 领域/`），需要追溯来源时再下钻到证据层（`30 证据/`）。回答附带 `[[wikilink]]` 引用。

### 3. 巡检（Lint）— 健康检查

```
对 wiki 做一次健康检查
```

检查项目：
- 孤页、死链
- 缺失 frontmatter、kind 或 layer
- raw 覆盖缺口（`raw -> source`）
- 编译完成度（`source -> atom/stable`）
- 孤立 atom、缺失领域地图、缺失决策边界

巡检报告写入 `wiki/00 系统/巡检报告/`。

## 目录结构

本知识库采用**分层知识架构**，包含六个逻辑层级：

```
raw/                          # 不可变源文档（LLM 只读）
├── 收件箱/                    # Web Clipper 统一入口
├── <领域>/                    # 按知识领域组织
└── assets/                   # 图片、附件

wiki/                         # LLM 维护的知识库
├── 00 系统/                   # 导航、规则、日志
│   ├── Wiki 目录.md           # 首页
│   ├── 知识库目标.md          # 使命、读者、范围
│   ├── 术语表.md              # 术语定义
│   ├── 操作日志.md            # 操作时间线
│   └── 评审规则.md            # 晋升标准
├── 10 核心/                   # 跨领域稳定知识
│   ├── 地图/
│   ├── 概念/
│   ├── 方法/
│   ├── 实体/
│   └── 综合/
├── 20 领域/                   # 各领域专属内容
│   └── <领域>/
│       ├── 领域地图.md
│       ├── 主题/
│       ├── 案例/
│       └── 工作台/
│           └── 原子卡/        # 原子知识草稿
├── 30 证据/                   # 来源摘要与摘录
│   ├── 资料摘要/
│   └── 摘录/
├── 40 问答/                   # 高复用问答页
└── 90 归档/                   # 已过时页面

canvas/                       # JSON Canvas 可视化地图
graph/                        # 可移植图谱导出
templates/                    # 页面模板（每种 kind 一个）
AGENTS.md                     # Wiki 规范 v2（唯一真相源）
CLAUDE.md                     # Claude Code 配置（导入 AGENTS.md）
```

### 晋升路径

```
raw -> source -> atom -> concept/method/entity/topic -> synthesis
```

- `source` 页是证据层草稿，不是最终稳定知识
- `atom` 卡是工作台中间态，一卡一事
- 稳定知识存放在 `10 核心/`（跨领域）或 `20 领域/`（领域内）
- 被 2+ 领域复用的内容，建议从领域层晋升到核心层
- 由 3+ 来源共同支持的新结论，建议晋升为 synthesis

### 仓库策略

- 同一 vault，同一 Git 仓库
- `raw/` 本地优先保留，默认不进远程
- `wiki/`、系统页、模板页允许推送远程
- 外部文档系统（如飞书）仅作为补充备份
